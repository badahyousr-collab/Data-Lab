# pipisso Data Lab

Учебный проект по обработке продаж вымышленного интернет-магазина: CSV → проверка и загрузка на Python → SQL → публичный дашборд. Вся информация демонстрационная.

## Что считается продажей

Подробные правила и ручной контрольный пример находятся в [docs/01-data-contract.md](docs/01-data-contract.md). Денежные значения хранятся в целых копейках. Выручка = подтверждённые платежи − завершённые возвраты. Неоплаченные заказы и незавершённые возвраты в показателях не участвуют. Средний чек считается по покупкам с положительной выручкой после возвратов. Повторный покупатель совершил минимум две такие покупки.

## Запуск

Требуется Python 3.11+. Основные этапы работают на стандартной библиотеке, без платных сервисов.

```bash
python -m datalab.cli seed --output data/demo
python -m datalab.cli load --input data/demo --database data/sales.db
python -m datalab.cli report --database data/sales.db
python -m datalab.cli export --database data/sales.db --output web/data.json
python -m unittest discover -s tests -v
python -m http.server 8000 --directory web
```

Откройте `http://localhost:8000`. Повторный `load` не удваивает записи. Некорректные записи отклоняются до изменения базы; конфликтующие дубли идентификаторов тоже отклоняются.

Отдельное сравнение на большом учебном наборе через PySpark описано в [docs/04-spark.md](docs/04-spark.md). Дашборд читает подготовленный JSON и не имеет доступа к базе или загрузке. Инструкция для бесплатной публикации через Cloudflare Workers Static Assets — [docs/05-deploy.md](docs/05-deploy.md).

## Структура

- `datalab/` — генератор данных, валидация и загрузка, экспорт.
- `sql/` — схема и аналитические запросы (SQLite с CTE, joins и оконными функциями).
- `spark/` — отдельная обработка больших наборов.
- `tests/` — контрольный расчёт, ошибка и повторная загрузка.
- `web/` — статическое публичное демо; `wrangler.jsonc` указывает Cloudflare папку с файлами.

Это портфолио, а не рабочая система магазина: источник данных синтетический, Python и Spark запускаются локально, обновление сайта происходит после повторного экспорта. SQL использует SQLite, чтобы любой мог запустить кейс без сервера; его можно перенести на PostgreSQL, но этот репозиторий не утверждает, что PostgreSQL уже реализован или проверен.
